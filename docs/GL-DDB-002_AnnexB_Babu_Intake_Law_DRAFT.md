## 1 · The Gate Sequence (every incoming file, no exceptions)

    ARRIVAL → B-1 ARCHIVE RITE → B-2 NERGAL AV → B-3 LICENSE CHECK
            → B-4 SLA FORMAT TEST → [pass] landing as particles
                                  → [foreign] B-5 AAOL MINTING PATH
                                  → [rejected] B-6 PDM RESTRUCTURING

**B-1 · Archive Rite.** A compressed file is itself an Identity particle.
Extraction is a rite: children are minted with NUZI lineage to the archive;
the original archive is retained sealed with its checksum (L-7 — the unpacking
is forever re-verifiable). Nested archives recurse the rite.

**B-2 · Nergal AV Portal.** Threat scan before anything else touches content.
Failure is not a formatting matter: the file routes to EnkiQDB as
evidence-grade quarantine (prune-exempt while PARZU open). No conversion, no
negotiation, no second pass without a new sealed decision.

**B-3 · License-Before-Conversion (non-negotiable order).** The license EAV
check runs BEFORE any AAOL conversion, because some proprietary formats
encumber decoding itself. The Golden Store must never hold a particle it had
no right to derive. license_id, terms_ref, and redistribution_flag are minted
here and inherited by everything downstream.

**B-4 · SLA Format Test.** The incoming structure is tested against the
approved format arsenal (SLA-compliant types). Pass → normal landing in
EnkiSDB under the GL-DDB-002 chunk law. Foreign-but-convertible → B-5.
Foreign-and-contested → Data Steward decision (the SLA dual-seal station of
the eight-step rite): approve-for-minting → B-5; reject → B-6.

## 2 · B-5 — The AAOL Minting Path (foreign format, Steward-approved)

The Akkadian aggregator's AAOL unit (AkkadianAOL — the full sovereign
Orchestration Language, bidirectional Core) handles the approved-foreign case:

1. AAOL generates the **.akk tablet** describing the foreign format and its
   mapping to sovereign structure (fields, encodings, loss notes with honest ε).
2. The tablet is compiled to a **.tmpl template particle** (GL-TPL-001 minting).
3. The template passes **Gate G4** — Z3 composite-satisfiability, design-time
   only. Templates are proven, never trusted; a format-template is a template.
4. On proof, the template receives its **KAKI v4.0** and becomes an official
   Particle; converted content lands as chunk particles citing template_kaki,
   conversion ε, and any declared loss (Truth Before Beauty applies to
   conversion: loss is recorded, never hidden).
5. Re-certification: like all .akk tablets, format templates can be
   regenerated against new release standards with Z3 re-proof at G4.

## 3 · B-6 — PDM Restructuring (Steward-rejected): the Shape Test

Rejection is geometry, not opinion. In DubSar PDM:

- Every approved template is a **reference simplicial complex** K_ref.
- An incoming structure S is admissible iff it admits a structure-preserving
  **simplicial map** φ: S → K_ref (Simplicial Complexity + Geometric Algebra
  tier of GL-ALG-002; TDA/persistence identifies which features of S obstruct
  the map — the rejection names the holes).
- Client-side parties restructure S and resubmit; each attempt is an Event
  particle (the negotiation has a StoryEngine journal; scars kept).
- When φ exists, S re-enters at B-4 as a candidate for the arsenal or for
  AAOL minting. The PDM validation stack applies as always: pure-Rust
  structural validation → NINSUN-class advisory → barû residuals → Z3 proof.
