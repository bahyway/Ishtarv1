## 0 · The Law (one sentence, everything follows from it)

**In BahyWay there is exactly one visual primitive: the particle. A node, an
edge, a label, an image, a concept, an instruction — none of these are distinct
kinds of thing. Each is a *pattern that particles form at a particular zoom
depth*. Zoom into any of them and it dissolves into its own constituent
particles.**

This is what Triple-O (Orbit-Oriented Ontology) means at the visual layer:
state is position, structure is pattern, and *every element is the same kind of
thing seen at a different scale.*

---

## 1 · Why this is THE difference from every knowledge graph

Ordinary knowledge graphs (Neo4j, Hetionet, PrimeKG, Open Targets, every dataset
diagram) are built on a **two-primitive ontology**: NODES and EDGES are different
kinds of object. A node contains; an edge connects. You cannot zoom into an edge
— it is a line, a leaf, terminal. Labels are decorations bolted on top.

BWVL is built on a **one-primitive ontology**: only particles.
- A "node" is a *dense cluster* of particles.
- An "edge" is a *filament* of particles streaming between clusters.
- A "label" is a *pattern* particles resolve into as text at close range.
- An "image" is a *particle field* that reads as a picture at a depth.
- A "concept", an "instruction", a "record" — all particle assemblies.

Node-ness/edge-ness/label-ness are **emergent, scale-dependent readings**, not
built-in types. This is not a stylistic choice; it is the ontology. It is why
BWVL can do what a knowledge graph structurally cannot: **zoom into a relation
until you reach the particles that constitute it** (the records, evidence,
sub-signs that *are* that relation), zoom into a node until you reach its
essential particles, zoom into a label until it dissolves into the data that
authored it.

## 2 · Consequences (what the law forbids and requires)

**Forbids:**
- Solid opaque node-spheres that do not dissolve (they are containers → banned).
- Hard vector edge-lines drawn *on top of* particle filaments (two primitives
  for one thing → banned). An edge is particles, full stop.
- A global fixed zoom ladder (D1…D7 as camera dolly) as the *only* navigation —
  depth is **local to the element you enter**.

**Requires:**
- Every rendered element is a particle assembly with an *interior*.
- Zoom/click on ANY element (cluster, filament, label, image) dissolves THAT
  element into its constituent particles — **local per-element depth**, not one
  global number. A relation has inner layers; so does a node; they differ.
- The "fuzzy far / structured near" transition is the *only* legibility
  mechanism. Far = density (cosmic web). Near = the particles resolve into the
  pattern (labeled graph). Same particles, different scale. No overlay.

## 3 · Local depth (the corrected navigation)

Depth is not a global tier stack. It is a **stack of what you have entered**:

    field  →  (enter a filament)  →  filament's particles: the records that are this relation
           →  (enter a cluster)   →  cluster's particles: the members that are this node
           →  (enter a label)     →  label's particles: the source text/evidence that authored it

A breadcrumb tracks *which element you are inside* (field › presents_in(sudden
death→anthrax) › record #4173), not a number 1–7. Ascending pops the stack.
Different elements expose different inner layers because they are made of
different particles — but all are *particles*, so the same zoom gesture works on
all of them.

## 4 · THE GENERATOR (why this matters more than any example)

The instrument is worthless as one hand-built disease-web. Its value is the
**runtime generator**: any stakeholder query, against the terabytes of GOLDEN
data, produces a BWVL scene automatically. The example is disposable; the
generator is the product.

**Generator pipeline (query → particle scene):**

1. **ASK** (HeptaScript, GL-HS3-001) — the query names entities / a question.
2. **PROVE / retrieve** — pull the grounded GOLDEN records from EnkiDB (OLTP) /
   EnkiDW (OLAP). Everything returned is already particles (KAKI-identified).
3. **Assemble patterns** — particles that co-ground an entity form a *cluster*
   (reads as a node); particles that ground a relation form a *filament* (reads
   as an edge); particles that are provenance/label text form a *label pattern*.
   No new primitives are created — only particles are *arranged*.
4. **Render by density** — far = cosmic-web field; near = resolved pattern. Four-
   outcome honesty (FACT/WEAK/GHOST/NONE) sets particle brightness/spread.
5. **Zoom = dissolve** — entering any assembly re-queries GOLDEN for *that
   assembly's* constituent particles and renders them, recursively, all the way
   to the essential particle (one KAKI record).

The same generator serves any domain (bacteriology, cardiology, veterinary) and
any query, because it never hard-codes nodes or edges — it only *arranges
particles retrieved at runtime*. This is the general instrument.
