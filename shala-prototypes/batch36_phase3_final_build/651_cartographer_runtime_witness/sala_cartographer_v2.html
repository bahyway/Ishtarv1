Cartographer v2 — read your own repo, and be told plainly what it cannot see 𒁾

Every edge here comes from static text: Cargo.toml for crates, import_playbook and the declared bahyway_requires / bahyway_provides contract for playbooks. Nothing is compiled and nothing is run. Nodes sit on concentric layers — layer 1 is buildable now, layer n only after every ring inside it. A relation binding three or more nodes at once (a playbook, the crates it builds, the services it leaves behind) is drawn as a filled simplex, not three lines. Gold marks the critical path: the longest chain, which is the true depth of the estate and the floor on how many rounds a rebuild can take. Violet marks an undeclared edge — inferred from text rather than declared, and therefore DERIVED, not MEASURED. v2: open a local playbook folder or a GitHub repository directly, and read the coverage panel — it names, by class, exactly which dependency kinds this survey can and cannot resolve.

STATIC SURVEY · READS ONLY WHAT IS WRITTEN · A STATIC GRAPH IS ONE WITNESS, NEVER TWO
Honesty: a static survey resolves declared and textually inferable edges only. It cannot see a dependency that exists solely at run time. The coverage panel states this per class, and PB-383 supplies the second witness.
