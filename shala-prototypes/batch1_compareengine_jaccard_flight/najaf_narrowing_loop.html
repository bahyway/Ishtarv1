𒁾 How the next question is chosen — not guessed, computed

Answer = geometric mask

"To the south" is a half-plane. "Near the big mosque" is a radius query. "Famous grave as anchor" is a bearing from a known point. Each answer is a boolean mask over the particle field — the exact dense, uniform work the engine does at 2.4B particles/sec.

Question = maximum information gain

Of all questions available, pick the one whose answer splits the surviving set most evenly. A question that rules out half is worth one bit; a question that rules out three graves is nearly worthless. The loop always asks the most-splitting question next — twenty-questions, made geometric.

-- the loop, in HeptaScript v2.0
PRESENT grave FROM najaf.field           -- N candidates
WITNESS memory "...music from the south..."  -- extract only the grounded part: SOUTH
LOOP UNTIL candidates <= 3:
  ORBIT question BY MAX_INFO_GAIN     -- pick most-splitting mask
  SYNC answer FROM mourner
  PROVE field MASK answer.geometry   -- billion-particle boolean, <1s
EMIT anchor AS plot_id
Charter notes. Rehearsal only (Way-of-Work rule 5). The sensory fragment ("sad music") is deliberately dropped — the loop keeps only what maps to geometry (south, landmarks, anchors). The masking step is where the billion-particle law lives: each answer is one dense SIMD pass over the field. Under NL-001 the engine is god-named (Nabû/NajafEngine); Najaf is a city and names the structure. Built with care: for a grieving person, the loop asks for a name or a landmark and does well with those, rather than promising the memory itself will find the grave.
